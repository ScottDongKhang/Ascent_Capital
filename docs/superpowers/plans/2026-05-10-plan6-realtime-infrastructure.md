# Plan 6 — Real-Time Infrastructure

> **For agentic workers:** Use superpowers:subagent-driven-development to execute task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Transform Ascent from a batch-processing system into a live, queryable, investor-presentable platform. Four components: (A) 1-minute bar streaming via Alpaca WebSocket replacing end-of-day Yahoo pulls for intraday monitoring, (B) TimescaleDB time-series database replacing the flat parquet cache as the system of record, (C) live dashboard showing real-time NAV, factor exposures, alpha sleeve IC, and event feed, (D) auto-generated monthly investor report in PDF format showing GIPS-compliant performance attribution.

**Architecture:** Streaming data flows into TimescaleDB. All system components (agents, optimizer, attribution, dashboard) query TimescaleDB as a single source of truth. The live dashboard is a Streamlit app (extending `demo_app.py`) that queries TimescaleDB directly. The monthly PDF report is generated by a Python script that pulls from TimescaleDB + log files. Parquet caches remain as a fallback for historical data that predates the TimescaleDB migration.

**Tech Stack:** Python 3.12, `alpaca-trade-api` (WebSocket), `psycopg2` + `timescaledb` (PostgreSQL + TimescaleDB Docker), `streamlit` (extending existing demo_app.py), `reportlab` or `weasyprint` (PDF generation), existing `ascent/dashboard/` modules.

**Prerequisites:** Plans 1–5 should be largely complete before this plan is implemented — the dashboard is only valuable if it has factor exposures (Plan 1), IS decomposition (Plan 5), and event feeds (Plan 3) to display.

**⚠ TimescaleDB migration is irreversible at scale.** Do not migrate historical data until the schema is finalized and tested. Run TimescaleDB in parallel with parquet for at least 30 days before cutting over completely.

## Task 1: TimescaleDB Setup

**File:** `ascent/data/store/schema.sql` and `scripts/setup_timescaledb.sh`

### Steps
- [ ] 1.1 Write `scripts/setup_timescaledb.sh`. One-command setup:
  ```bash
  docker run -d --name timescaledb -p 5432:5432 \
    -e POSTGRES_PASSWORD=ascent \
    -e POSTGRES_DB=ascent \
    timescale/timescaledb:latest-pg15
  ```
  Waits for readiness, then runs schema.sql.
- [ ] 1.2 Write `ascent/data/store/schema.sql`. Tables:
  - `prices_1m(time TIMESTAMPTZ, symbol TEXT, open FLOAT, high FLOAT, low FLOAT, close FLOAT, volume BIGINT)` — hypertable partitioned by time, 1-week chunks.
  - `prices_1d(time TIMESTAMPTZ, symbol TEXT, open FLOAT, high FLOAT, low FLOAT, close FLOAT, volume BIGINT, adj_close FLOAT)` — hypertable, 1-month chunks.
  - `factor_scores(time TIMESTAMPTZ, symbol TEXT, sleeve TEXT, score FLOAT)` — hypertable.
  - `portfolio_state(time TIMESTAMPTZ, agent_id TEXT, symbol TEXT, weight FLOAT, alpha_score FLOAT)` — hypertable.
  - `nav_series(time TIMESTAMPTZ, agent_id TEXT, nav FLOAT, daily_return FLOAT, spy_return FLOAT)` — hypertable.
  - `factor_exposures(time TIMESTAMPTZ, factor TEXT, exposure FLOAT, variance_explained FLOAT)` — hypertable.
  - Continuous aggregates: daily OHLCV from 1-minute bars (auto-updated by TimescaleDB).
  - Compression policy: compress 1-minute bars older than 7 days.
  - Retention policy: keep 1-minute bars for 90 days; daily bars forever.
- [ ] 1.3 Add `TIMESCALEDB_URL` to `.env` template: `postgresql://postgres:ascent@localhost:5432/ascent`. Document in README setup section.

## Task 2: TimescaleDB Interface

**File:** `ascent/data/store/timescale.py`

### Steps
- [ ] 2.1 Write `get_connection() -> psycopg2.connection`. Lazy singleton. Reads `TIMESCALEDB_URL` from environment. Returns `None` (not raises) if DB unavailable — all callers must handle None gracefully.
- [ ] 2.2 Write `write_prices(df, table="prices_1d") -> bool`. Accepts a DataFrame with columns `[time, symbol, open, high, low, close, volume]`. Bulk inserts using `psycopg2.extras.execute_values`. Returns True on success, False on failure (logs error). Uses `ON CONFLICT DO NOTHING` to handle duplicate writes.
- [ ] 2.3 Write `read_prices(symbols, start, end, table="prices_1d") -> pd.DataFrame`. Returns a DataFrame indexed by time with symbol as column. Uses TimescaleDB time_bucket for 1-day aggregation if reading from 1-minute table.
- [ ] 2.4 Write `write_factor_scores(date, agent_id, scores_df) -> bool`. Accepts a DataFrame with columns `[symbol, sleeve, score]`. Bulk inserts to `factor_scores` table.
- [ ] 2.5 Write `write_portfolio_state(date, agent_id, weights_dict, alpha_scores_df) -> bool`. Inserts to `portfolio_state` table.
- [ ] 2.6 Write `write_nav(date, agent_id, nav, daily_return, spy_return) -> bool`. Inserts to `nav_series`.
- [ ] 2.7 Write `write_factor_exposures(date, exposures_series) -> bool`. Inserts to `factor_exposures`.
- [ ] 2.8 Write `timescale_available() -> bool`. Simple liveness check — tries `SELECT 1`; returns True/False. Called at startup; if False, system operates in parquet-only mode with a one-time log warning.
- [ ] 2.9 Modify `ascent/data/store/parquet.py`: after every `save_parquet()` call, attempt `write_prices()` to TimescaleDB. Wrap in try/except — parquet save still succeeds even if DB write fails.

## Task 3: Alpaca WebSocket Streaming

**File:** `ascent/data/streaming/alpaca_stream.py`

### Steps
- [ ] 3.1 Write `start_stream(symbols, on_bar_callback) -> threading.Thread`. Connects to Alpaca WebSocket data stream (`wss://stream.data.alpaca.markets/v2/iex` for free plan). Subscribes to 1-minute bars for all symbols. On each bar, calls `on_bar_callback(bar_dict)`. Runs as a daemon thread.
- [ ] 3.2 Write `default_bar_callback(bar) -> None`. Writes the bar to TimescaleDB `prices_1m` table and updates an in-memory price cache (a dict `{symbol: last_price}`). Also updates live NAV estimate.
- [ ] 3.3 Write `get_live_price(symbol) -> float | None`. Returns the last price from the in-memory cache. Returns `None` if not yet received (on startup or for symbols not in stream). Callers fall back to last daily close in this case.
- [ ] 3.4 Reconnection: on WebSocket disconnect, retry with exponential backoff (1s, 2s, 4s, max 60s). Log each reconnect. Never crash the main process on stream failure.
- [ ] 3.5 Universe limitation: Alpaca's free IEX feed can handle ~1,000 concurrent symbols. The 901-symbol US equity universe fits. Subscribe on startup and keep the subscription live. Do not re-subscribe on reconnect for symbols already in the list.
- [ ] 3.6 Wire into `run_all_agents.py`: start stream thread at startup (before agent runs). Stream runs all day. Market hours check: Alpaca's stream only delivers data during market hours; the thread runs but receives no bars outside 9:30–16:00 ET.

- [ ] 4.5 Write `get_nav_series(lookback_days=252) -> pd.DataFrame`. Reads from TimescaleDB `nav_series` table. Falls back to `logs/us_equities_pnl.jsonl` if DB unavailable.

## Task 6: Monthly Investor Report

**File:** `ascent/reporting/investor_report.py`

### Steps
- [ ] 6.1 Install PDF generation: `pip install weasyprint`. Weasyprint converts HTML → PDF. Use Jinja2 (already likely available) for HTML templating.
- [ ] 6.2 Write `generate_monthly_report(year, month, output_path) -> Path`. Assembles a PDF report from the following sections:
  - **Cover page**: strategy name, reporting period, NAV as of month-end.
  - **Performance summary**: monthly return, YTD return, since-inception return. SPY comparison for all three. Sharpe ratio (annualized). Max drawdown since inception. Table in GIPS-compliant format.
  - **Attribution**: factor-explained vs. idiosyncratic P&L (from attribution log). Top 5 contributors and detractors by position. Sleeve-level P&L breakdown.
  - **Risk summary**: average VaR (95%), average factor exposures, number of intraday trigger activations, IS decomposition (average delay cost / market impact / opportunity cost).
  - **Trade summary**: total rebalances, average turnover, average slippage (gross and net). Event trades: count, IC, average size.
  - **Strategy commentary**: 2–3 paragraphs auto-generated by Haiku summarizing regime environment, portfolio positioning, and alpha sleeve performance during the month.
  - **Disclosures**: standard risk disclosure language (auto-generated by `compliance/risk_disclosure.py` from Plan 7).
- [ ] 6.3 Write `schedule_monthly_report()`. Called on the first Sunday of each month (reuses existing monthly trigger). Generates report for the prior month. Saves to `outputs/investor_reports/YYYY-MM.pdf`.
- [ ] 6.4 Wire into `run_all_agents.py` monthly trigger block.

## Task 7: Alert System

**File:** `ascent/monitoring/alert_system.py`

### Steps
- [ ] 7.1 Write `check_alerts(portfolio_state, live_nav) -> list[dict]`. Three alert categories:
  - **Drawdown alert**: intraday drawdown > 5% → WARNING log. > 10% → CRITICAL log + optional email/push notification.
  - **Factor exposure breach**: any factor exposure outside ±0.6σ → WARNING log.
  - **Sleeve IC degradation**: trailing 21-day IC of any sleeve < −0.01 → WARNING log (sleeve may be failing in current regime).
- [ ] 7.2 Write `send_alert(alert_dict) -> None`. For now: write to `logs/alerts.jsonl` and log at appropriate level. Future: integrate with ntfy.sh (free push notifications, no account needed) via a single POST request. Add `NTFY_TOPIC` to `.env` template.
- [ ] 7.3 Deduplication: do not resend the same alert type for the same symbol/factor more than once per 4 hours. Track last-sent timestamps in `logs/alert_state.json`.
- [ ] 7.4 Wire into `eod_runner.py`: call `check_alerts()` at the start of every run.
